# Hill-Climbing Workspace Layout

The hill-climbing skill maintains an internal workspace to track iterations, evaluation reports, and mutation history. All paths are relative to `<workspace_root>` (default `.context-engineering/experiments/<experiment_name>/`).

## Directory structure

```
<workspace_root>/
├── state.md                       # metadata + per-iteration scores + notes
└── v<N>/                          # one directory per iteration (v0 = base, v1+ = mutations)
    ├── context_set_v<N>.json      # ContextSet snapshot at this version
    ├── analysis_v<N>.md           # findings + reasoning + mutations applied
    └── eval/                      # output_dir for context-engineering-evaluate
        ├── eval_configs/          # generated Evalbench YAMLs + converted dataset
        │   ├── db_config.yaml
        │   ├── model_config.yaml
        │   ├── run_config.yaml
        │   ├── llmrater_config.yaml
        │   └── golden_queries.json
        └── eval_reports/<job_id>/
            ├── scores.csv
            └── summary.csv
```

## `state.md` format

`state.md` is the single source of truth for iteration progress. It must contain:

- **Metadata** — experiment name, workspace root, golden dataset path, DB source (from `tools.yaml`), and the Context Store coordinates: `project_id`, `location`, `context_set_id`. From these, the final resource is `projects/<project_id>/locations/<location>/contextSets/<context_set_id>` and iteration `N`'s transient draft is `projects/<project_id>/locations/<location>/contextSets/<context_set_id>_draft<N>`. If `v0` was seeded from a user-supplied existing resource, record that resource name under `Seed resource` so it is never treated as a draft.
- **Iteration Log** — one entry per completed iteration, in order. Each entry records the local file, the score, the draft's upload and delete operation names, and `Draft: deleted`.
- **Final** — written once by the Finalize step.

Example:

```markdown
# Hill-Climbing Experiment: my-exp-1

## Metadata
- Workspace: ./.context-engineering/experiments/my-exp-1/
- Golden dataset: ./golden.json
- DB source: my-alloydb
- Project: my-project
- Location: us-central1
- Context set id: my-exp-1
- Final resource: projects/my-project/locations/us-central1/contextSets/my-exp-1
- Draft pattern: projects/my-project/locations/us-central1/contextSets/my-exp-1_draft<N>
- Seed resource: (none — seeded from bootstrap)

## Iteration Log

### v0 (base)
- Local file: v0/context_set_v0.json
- Draft: my-exp-1_draft0 — deleted
- Upload op: projects/my-project/locations/us-central1/operations/operation-...-a1
- Delete op: projects/my-project/locations/us-central1/operations/operation-...-a2
- Score: 0.42
- Eval report: v0/eval/eval_reports/<job_id>/
- Notes: baseline generated by context-engineering-bootstrap

### v1
- Local file: v1/context_set_v1.json
- Draft: my-exp-1_draft1 — deleted
- Upload op: projects/my-project/locations/us-central1/operations/operation-...-b1
- Delete op: projects/my-project/locations/us-central1/operations/operation-...-b2
- Score: 0.58
- Analysis: v1/analysis_v1.md
- Eval report: v1/eval/eval_reports/<job_id>/

### v2
- Local file: v2/context_set_v2.json
- Draft: my-exp-1_draft2 — deleted
- Upload op: projects/my-project/locations/us-central1/operations/operation-...-c1
- Delete op: projects/my-project/locations/us-central1/operations/operation-...-c2
- Score: 0.55
- Analysis: v2/analysis_v2.md
- Eval report: v2/eval/eval_reports/<job_id>/

## Converged: v2 regressed; no new failure categories to address

## Final: projects/my-project/locations/us-central1/contextSets/my-exp-1 (from v1, score 0.58)
```

## Markers

`state.md` carries markers that let a resume distinguish crash, intentional stop, user stop, and an interrupted finalize:

- `## In-Progress: vN` — written at the start of iteration N (per-iteration step 1); removed when the final `### vN` entry lands (per-iteration step 7). A leftover marker means the prior run crashed mid-iteration — possibly with `<context_set_id>_draftN` still present in the store.
- `## Converged: <one-line reason>` — appended when the agent judges improvements dry.
- `## User Stop` — appended when the user explicitly asks the loop to stop.
- `## Finalizing: vK` — written immediately before the final upload; replaced by `## Final: …` when that upload's operation reports `done: true`. A leftover marker means the final upload was interrupted.

Completed iterations are preserved in every case — never deleted.

## Resume rules

On skill invocation with an existing workspace:

1. Read `state.md`.
2. Determine the last completed iteration `N`.
3. **Check for `## In-Progress: vM`.** If present, the prior run crashed mid-iteration `M`:
   1. Call `delete_context_set` on `<context_set_id>_draftM` and poll `get_operation` until `done: true`. A NOT_FOUND response counts as success — the draft may already have been swept.
   2. Delete the partial `vM/` directory (its files are not trustworthy) and remove the marker.
   3. Re-run iteration `M` from step 1, seeding from `v(M-1)/context_set_v(M-1).json` on disk.
4. **Check for `## Finalizing: vK`.** If present, the final upload was interrupted. Re-confirm the final resource name with the user (it is an overwrite), re-run the Finalize step from `vK/context_set_vK.json`, and poll until `done: true`.
5. If `## Final:` is present, report it and stop — the run is complete.
6. If `## Converged` or `## User Stop` is present without `## Final:`, run the Finalize step — do not start another iteration.
7. Otherwise, start iteration `N+1`.

## Final output

The resource recorded under `## Final:` — the bare `<context_set_id>` uploaded from the best-scoring iteration's local file — together with that score and local file path. No `_draft` resource should remain in the store when a run is complete.
